The first beta of LivePace 0.8.0. The technical details are below, highlights are:

  • A step-by-step run wizard for creating new runs, group runs, etc
  • Lots of bugfixes and stability improvements
  • Both Android and iOS apps are now in open beta, available from the stores, and the Garmin app has been submitted for approval.

To install, follow the appropriate link here:

Android

iOS

Note that installing on iOS will require setting up TestFlight until it's released publicly.

Garmin

Please update if you share your position

Existing users (the very few!) will need to update to connect to the updated servers.

The Run Wizard (new)

Planning a run is now a short full-screen wizard in the style of the first-run setup, one question per page, the same pages and words on both apps. It opens from every place a new run is begun: PLAN RUN on the home screen, New run in the run list, a long press on a day of the calendar, a GPX file opened with LivePace, a group-run link, Add on a public race, and “Select race” or “Choose group run” in the Live Tracking settings. The run editor is still there for every detail, and for changing a run that exists.

  • Four kinds of run. “What are you planning?” offers a training run, creating a group run, joining a group run, and joining a race. The three that use the server need live tracking with a share code; until you have one their cards are dimmed with a link to the Live Tracking settings, and the wizard is waiting for you when you come back.
  • A training run asks when (Today, Tomorrow or a picked date, the start time, and “Start automatically at this time”), where (a GPX route, a distance typed or chosen from 5k, 10k, 10mi, Half and M, or just a planned time), and how fast. The review shows it all with an “(edit)” on each line, and ends in “Create run”, “Create and add checkpoints” or “More details” (the run editor). The run is named after the time of day of its start (“Morning Run”) unless you type a name.
  • Your pace, three ways. Manual (two ends, or one pace with a margin either side), Training Pace (one of your training-pace bands, or a training pace with a margin), and Finish Time (a goal time over the run’s distance, with the goal as the middle of the range or as its slow end). Under them, Targets shows the pace range and the predicted finish.
  • Create a group run: its name and start, its routes (GPX files, and whether runners may join without a route), and its start, finish and support points placed on a map that shows the routes. The group run is then created on the server, and its page shows the code to share (copy, share link or QR code) and asks “Do you want to participate in this run?”. Yes takes you through the join; No leaves you as the organiser only.
  • Join a group run with its code or link, or from “Your group runs”. When it has several routes you pick one.
  • Join a race: search the race list by name, narrow it by country, region and city, and by date (“Upcoming”, “All dates” or a month). Then choose your start wave and route, and set your goal.
  • A run you already have. When you pick a race or group run you already have a run of, the wizard asks first: edit the existing run, delete it and make a new run, or make another run beside it.
  • Nothing half done. Nothing is saved or sent until the review’s button, which then saves the run and tells the server step by step. A step that fails (no network, a server error) is shown with Retry, which sends only what is still owed; a group run is never created twice. A run made while another run is recording is saved without being opened, and you are told where to find it.
  • First-run setup takes the same look: the buttons sit at the bottom of the screen with the question above them.

Runs, Marks, Pauses and the Finish

  • No accidental marks. For 5 seconds after any start the Mark control is dimmed and ignores taps, so a second tap where Start was records nothing. A mark more than 200 m (and more than 3 percent) away from the GPS distance is asked about before it is recorded. Every mark from the Mark control can be undone for 10 seconds from the run screen, and undoing a mark that replaced an earlier one at the same distance asks whether to bring the earlier one back.
  • One kind of pause. Every pause, from the Pause button, its long-press menu, the watch or the “You appear to have stopped” prompt, is a rest break, and the separate “Pause (no break)” is gone. A pause left for an hour asks “You appear to have stopped” (Resume, Finish or Stay paused), with GPS at its low-power rate until you answer.
  • Standing still is noticed. “You appear to have stopped” now also comes when a phone that is lying still delivers no GPS fixes at all, offers a stop time from the start of the slow-down (never before your latest resume), and is no longer raised because location was switched off.
  • Late planned starts are asked about. A planned run first opened more than 10 minutes after its start time asks “Start this run?” (from the planned time or from now) instead of starting by itself. The home-screen reminder for a planned run that has not been opened is worded by whether the run starts automatically.
  • Start and finish lines. A start-line crossing is taken only from a GPS fix at the start of the route and is timed at the fix nearest the line, and the fix that starts a waiting run is recorded as its first. “At finish line”, and the automatic finish after a finish-line crossing, now finish the run at the crossing rather than when you answer; a runner who stands still after the line is finished automatically. On iOS “Finish line detected” is also posted when LivePace is not in front.
  • The summary of a finished run shows the distance you covered (not the planned route’s length), a finish distance you typed as typed, the start time as a time of day, kilometre or mile splits and pace bars that end at the finish and add up to the summary, and the elevation from start to finish. The run screen and the recording notification show the distance covered too, and no live pace is shown while you stand still.
  • Runs in miles show their distances, paces, maps, pace bars and training sections in miles throughout, a pace typed with the other unit’s suffix (“/km”) is converted, and changing the display unit no longer rewrites the open run’s distance and paces. On iOS, Start no longer changes a run’s planned distance and paces by rounding them in the display unit.
  • The run editor fills the date, start time and name from a race or start wave you pick, and the distance from a GPX route you import (on Android also from a race’s route); an existing run is edited in its own unit, and a value you leave as it is stays exactly as it was. On Android, a new or unstarted run has the switch “Start automatically at ”.
  • Share works on a run with no planned distance or pace (it shares the run so far) and from a finished run’s review and summary, with the same text on both apps. Duplicate opens the run editor filled with everything the run planned.
  • Training runs. Each section of a training plan runs its own length from where it began. “Calculate from recent runs” lists each finished run with the distance it had covered at its finish and its time from its start, the same way on both apps, so a run finished early no longer counts as a faster one, a run closed later without a mark at its finish is timed to its last mark, and a run recorded with no planned distance is listed too.
  • If the phone’s clock is set back during a run, every fix is still recorded and the distance carries on from the next fix.
  • On the home screen a paused run of today offers Open, and on iOS today’s finished runs are listed with View, as on Android.

Free Tier

  • One rule for starts on both apps. Every start counts against the free tier’s 3 starts in 183 days, whatever makes it: Start, the clock, a start-line crossing, the watch, the late-start question, or a first mark. A start the limit refuses changes nothing (a refused first mark is not recorded). You are told when you arm an automatic start that the limit will refuse, and on Android a start the limit refused while the app was closed is explained when you next open it. On Android a failed purchase check no longer marks a paying user as unpaid.
  • Which 5 runs you can use is decided by one rule on both apps: runs under way or paused first, then the open run, the nearest upcoming runs and your latest past run. Every list shows all your runs and greys the others; a tap on a greyed run offers the upgrade, and you are told when a new run puts others beyond the 5. Once you have paid every run is usable at once, on the home screen as well as in the lists, and if the paid status lapses the limit applies again.

Live Tracking and Following

  • ”Stalled”. The Live Tracking status now says “Stalled” when nothing has got through on any channel for 90 seconds, with the reason when one is known. A position the server refused is no longer shown as delivered.
  • Your device key looks after itself. A device key whose packet counter cannot be used is replaced on its own and registered under the same share code. On iOS, a share whose stored identity was damaged is fetched back from the server.
  • Requests you make (register a share code, delete your data, set your race, add a code to follow) wait their turn instead of being refused while another is busy; each button shows only its own progress, and a request that fails is reported where you made it, in words you can act on. The run editor and the calendar say that a share code is needed before you fill in the form, with a Register button.
  • Start waves. A run of a race whose wave is not chosen gets the race’s only wave by itself, or shows “Choose a start batch”.
  • The leaderboard times each runner from the start their phone reports, with a switch on the web board to time everyone from the race’s start. Joining a group run again after finishing it starts a fresh row, and a row follows a change of wave or route. On the web board a stopped runner reads “Stopped”, and the map’s prediction label says when a runner is off their route.
  • Old positions stay old. A position kept by the server is never taken for a fresh one, a position is served for four hours from when the phone took it, and the watch lists only followed runners whose position is less than 10 minutes old.
  • The Live Tracking map shows a runner’s own route, never a followed runner’s, and with no route of your own the route most of the people you follow are on. On Android the route now changes with the people you follow while the map is up: it goes when nobody you follow is on one, and when you remove the last of them, whether or not they have sent a position yet. On iOS the map follows a change of route, and only your own gesture stops the camera following.
  • Following. A runner who has finished shows no finish prediction, predictions carry on from when each position was taken, and your own position when the Live Tracking screen opens is a fix at most 5 minutes old. On Android, Track Runners keeps up with several runners updating every few seconds, and a long route name or runner name no longer pushes the age and Remove off the row.

Maps and Routes

  • Route files are kept exactly as you sent them, so a GPX file in another character set keeps its accented names on the phone, the server and other runners’ phones. Android reads a GPX file in the encoding it declares.
  • Checkpoints on maps. An unnamed checkpoint is labelled with its distance in the unit the map shows (“3 mi”, “4.8 km”), and in a run measured in miles the runner and the checkpoints passed are drawn in the right place. On iOS a checkpoint you edit, add or remove moves on the full map at once.
  • The placement map of a group run draws its routes and frames them before any point is placed.
  • Offline maps are fetched for the run whose route they are, when the run is saved.
  • Elevation strip. On iOS a tap on a checkpoint icon opens Checkpoint Info; on Android a long press on one opens only Add checkpoint.
  • Run calendar. In Public races, a tap on a race in List view opens its details, as in Month and Week view. On Android the calendar’s toggles fit on screen in two rows.

Garmin Watch

The watch app has not changed, and the phone side of the link is steadier:

  • A watch app that is restarted is recognised, so its messages are no longer reported out of order.
  • On Android a start made on the watch is applied as its message arrives and stored at once, with or without the app on screen.
  • The question the watch’s stop raises waits for your answer, goes away with a resume or a finish, and its finish records the distance covered.
  • Watch positions are judged by their own time, are kept once in the run’s data and come back with it; on iOS the link to the watch carries on through a pause.

Reliability: Data Kept, Nothing Blocking the Screen

  • A run’s data is kept. The run being recorded cannot be deleted from the run list. Undoing or deleting a mark is recorded in the run’s data, so a reopened run shows the marks it has. A route removed in the editor stays removed. A run that has not started is never closed as finished at launch. On iOS a run reset and started again records into its file.
  • No blank runs left behind. Discard run and a Record run left blank no longer leave an empty run in the list, and on iOS opening a run after a fresh launch no longer writes an “Untitled race”.
  • The screen does not wait. Run files, run lists, routes and GPX files are read in the background on both apps. The run list and calendar draw only the rows on screen, so a long list scrolls smoothly; reopening a run long after its finish-line crossing no longer holds up the launch; and the Android home screen shows your share code as soon as the app starts.
  • Low storage. On Android the recorder pauses when storage runs out and goes on when space is back; on iOS the low-storage note is shown on the run screen as well.
  • GPS follows your settings. On Android the GPS tracking switch in Settings > Sensors now works. On iOS the location session follows the power mode in effect (the low-battery switch really lowers GPS use), a revoked location permission stops it at once, and iOS no longer pauses a tracked run’s location by itself.
  • The raw data files of finished runs are kept 7 days by default in release builds (the setting “Keep raw run logs for N days”).

Android-Specific

  • The auto-start alarm with the app closed no longer crashes: the run is started and a notification says it is not being recorded until you open the app.
  • After you swipe LivePace away in the recent apps, its notification says the app is closed and what goes on for your run, with Stop.
  • Settings. The Training paces page shows your paces, and keeps a calculation, after Live tracking or Connected Devices has been opened from Settings.
  • Fixes. OK in “Edit checkpoint” keeps the distance you typed, the Mark control offers the next distance straight after a mark or an undo, an undone mark no longer counts in the predictions, the run list shows each run’s distance, time and pace again, decimal commas are accepted in the checkpoint, distance and checklist fields, and leaving Subscription or the calendar in supporter mode returns to the supporter home.

iOS-Specific

  • No more surprise prompts. The countdown no longer asks for notification permission (Sensors & Permissions has a Notifications row instead), and a question that arrives while a sheet is closing is asked once it has closed.
  • Menus. A long press on Resume resumes, a long press on Finish opens its menu instead of finishing the run, the Pause and Finish menus show their titles, and “Resume this run?” offers Resume and Finish only.
  • Live tracking. A start time changed in the running run’s editor reaches the leaderboard at once, and “Choose a start batch” and My Races’ “active” label now show.
  • Create group run offers no Create until a share code is registered.

Known Issues

  • A GPX file over 4 MB picked for a group run is accepted, but its upload is refused at every Retry.
  • The run editor’s placement map for an existing group run can open with no route drawn.
  • A training section moved past by hand is forgotten when the app is restarted mid-run.
  • On Android, after LivePace is swiped away in the recent apps, a running run’s distance stops growing and the watch link stops until the app is opened again; the fixes are still recorded.
  • On Android a tap on the Mark control while it shows “GPS” does nothing (on iOS it records a mark).
  • On iOS the public races calendar cannot be opened without a share code.
  • Garmin device linking doesn't work in the Android release build.
